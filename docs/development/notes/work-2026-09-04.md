## STAGE C — UI/UX & CSS Refactor (2026-09-05) — THIS SESSION

### Issues Fixed (from user's repeated reports)

1. **Window auto-grows with tab count** → Fixed: `tab_scroller_` policy = `EXTERNAL` (horizontal). ScrolledWindow no longer propagates child's natural width; overflow handled by dedicated `Gtk::Scrollbar` below tab row. Window width stays fixed.

2. **Horizontal scrollbar overlaps tab labels** → Fixed: scrollbar now in its own row (`tab_box_` vertical box) below the tab row (`tab_row`), never overlapping label area. Visibility toggled via hadjustment changes (event-driven).

3. **+ New Terminal / + New Note buttons not square / too tall** → Fixed: `set_valign(CENTER)` + `set_halign(CENTER)` on buttons; removed top/bottom margins on `tab_actions`; CSS `min-width: 28px; min-height: 28px; padding: 0; border: none; box-shadow: none; outline: none;`. Buttons stay perfectly square, centered vertically in row.

4. **Native window controls (min/max/close) have black border in dark theme** → Root cause: global `button { border: 1px solid @border }` applied to headerbar titlebuttons. Fix: added explicit titlebutton rules in **both** dark.css and light.css (identical — `transparent` bg, no border, no outline, no box-shadow for all states: `:hover`, `:active`, `:focus`, `:checked`). Consistent appearance across themes.

5. **Tab close (×) button hover not round / too tall** → Fixed: `set_valign(CENTER)` + `set_halign(CENTER)` on close button in code (prevents vertical stretch to tab height). CSS hover `border-radius: 9999px` + `min-width/height: 18px` → true circle.

6. **Context menus have rectangular frame / colored background / wrong margins** → Root cause: custom `Gtk::Popover` + `Gtk::Button` items with CSS `margin: 4` on container. Fix: rewrote `ContextMenu` to use **native `Gtk::PopoverMenu` driven by `Gio::MenuModel` + per-item `SimpleAction`**. Now renders through exact same CSS nodes as note editor's native right-click menu (`popover.background.menu` + `modelbutton`). No custom frame, margins, or "card" styling. Unified across terminal panes, directory tree, and everywhere else.

7. **Toolbar icons not rendering (Find/Replace, Split Preview, etc.)** → Root cause: `Gtk::Image("icon-name")` constructor treats string as **filename**, not icon name. Fix: all icon creation changed to `Gtk::Image()` + `set_from_icon_name("...")`. Affected: `make_tool_btn()`, find bar icons (find, replace, prev, next, close).

8. **SVG red broken-icon placeholders** → Root cause: same filename-vs-icon-name bug above. Fixed by proper icon-name loading.

9. **Directory tree path label not below search/reload** → Already implemented: header = vertical box; top row = search + reload; second row = path label (`remin-dir-path`). Reload button: transparent, icon-only, 24×24 (CSS `.remin-dir-reload`).

10. **Directory tree not realtime / reload button** → FileMonitor with 150ms debounce already wired. Added `set_file_saved_callback` on NoteTabView → fires `directory_panel_->refresh()` only on **actual file write** (Ctrl+S, Save As), NOT on every keystroke. Separated from save-state callback (which fires for dirty dot).

11. **Dirty dot (●) only shows on tab switch** → Root cause: relied only on `signal_modified_changed`. Added belt-and-suspenders: also connect `signal_changed` with 120ms debounce in `NoteTabView::connect_editor()`. Persistent tab widgets (`tab_widgets_` vector) allow in-place label updates without full rebuild → cheap live dot.

12. **Tab bar full rebuild on every change** → Refactored `update_tab_bar()` to maintain `tab_widgets_` (parallel to `tabs_`). On pure append (new tab): add widget, refresh. On shrink (close): full rebuild (indices shift → widget identity breaks). On label change (dirty dot): `refresh_tab_widget()` updates text/active class in place.

13. **Directory tree: ".." chevron confusing / should navigate up** → Fixed: `..` row now single-click navigates to parent (`set_root(full_path)`); no expander arrow shown (opacity 0). **Label changed to "Back .."**. Regular dirs: single-click expands inline; **double-click enters** (navigation). Empty dirs: double-click enters.

14. **Scrollbar hover animation/accent color lag** → Removed `transition: background-color 0.15s ease` from `.remin-tab-scrollbar slider`. Global scrollbar: slimmed (8px min-width/height, slider 6px, margin 1px). Hover: neutral muted color (no accent), no animation.

15. **Native context menus use light background in dark theme** → Added `@define-color popover_bg_color @surface; @define-color popover_fg_color @text;` to theme var block in both themes. Native `Gtk::PopoverMenu` now follows app palette.

## Open questions / risks

- Whether to keep the in-progress (uncommitted) cosmetic changes from the
  previous pass or fold them into the refactor.
- GtkSourceView gutter renderer must get line info from GtkSourceGutterLines
  (not re-guess); confirm C API for wrapped-line iteration.
  
  Em chọn **1 — C API qua thin adapter**.

Lý do: trong stack GTK4 hiện tại, `GtkTextView` quả thật đã có gutter native (`set_gutter()` / `get_gutter()`), và GTK4 cũng có API khái niệm *display line* để xử lý wrapped lines. ([Gnome Pages][1]) Nhưng nếu Remin muốn editor có **line number + click marker + current-line + sau này syntax highlighting/search/replace** thì GtkSourceView 5 mới là stack chuyên dụng; nó kế thừa `GtkTextView`, có gutter native và `GtkSourceGutterLines` được thiết kế để cache/chia sẻ thông tin line khi render. ([Gnome Pages][2])

Quan trọng: **không cài thêm repo ngoài chỉ để kiếm C++ bindings**. GtkSourceView 5 cung cấp C API chính thức qua `gtksourceview-5`; cứ bọc nó trong một adapter C++ mỏng. ([Gnome Pages][2])

Gửi agent nguyên đoạn này:

```text
Chọn 1 — C API GtkSourceView 5 qua thin C++ adapter.

Không chọn 2.
Không thêm repository/source ngoài chỉ để tìm gtkSourceView C++ bindings.

Stack:

NoteEditor (C++)
    ↓
GtkSourceViewAdapter (C++)
    ↓
GtkSourceView 5 C API
    ↓
GtkTextView layout
    ↓
GtkSourceGutter / GtkSourceGutterLines
    ↓
GTK4

Requirements:

1. GtkSourceView 5 là editor engine, không expose C API khắp codebase.
2. Tạo một thin adapter riêng, ví dụ:

src/gui/editor/
├── note_editor.*
├── source_view_adapter.*
└── gutter_renderer.*

3. NoteEditor chỉ làm việc với adapter/abstract editor API.
4. Không để raw GtkSourceView/GtkSourceGutter C structs leak vào WorkspaceCore,
   NoteDocument hoặc SessionController.

5. Dùng native GtkSourceView gutter cho:
   - line numbers
   - current-line indicator
   - future line marks
   - clickable navigation

6. Không tạo:
   TextView(editor)
   +
   TextView(gutter)
   +
   manual scroll synchronization.

7. Không tự tính line height để giải quyết soft-wrap.
   Gutter renderer phải lấy layout/line information từ GtkSourceView /
   GtkSourceGutterLines.

Acceptance:

Logical line 42 wrapped thành nhiều visual rows:

42 | very long text...
   | continues...
   | continues...

Line number 42 phải nằm chính xác theo toàn bộ visual extent của logical line.

Phải giữ đúng khi:
- resize
- soft-wrap on/off
- font change
- theme change
- large document
- empty lines

Click line number:
- jump tới logical line
- scroll tới vị trí
- temporary navigation highlight
- đây KHÔNG phải clipboard selection

Không dùng:
- magic offsets
- guessed line heights
- polling vadjustment
- sleep/timer synchronization hacks.

TRƯỚC KHI CODE:

Kiểm tra version GTK4 + GtkSourceView 5 thực tế trên máy build.
Kiểm tra symbol/API cần dùng.
Xác nhận thin adapter interface.

Sau đó mới implement.

Bonus:
Tận dụng GtkSourceView cho các feature editor đã tồn tại thay vì tự
implement lại nếu API phù hợp:
- line numbers
- current line
- search/replace
- file loading/saving
- syntax highlighting

Nhưng không để GtkSourceView API làm domain model của Remin.
```

Và đây là một quyết định em thấy **rất đáng giá cho Remin**: dùng GtkSourceView 5 cho **Editor**, còn VTE cho **Terminal**. Hai cái đều là thư viện chuyên dụng, đúng philosophy của anh:

```text
Terminal
   → VTE

Markdown Editor
   → GtkSourceView

Workspace
   → Remin tự xây
```

GtkSourceView 5 vốn đã cung cấp line numbers, current-line, search/replace, syntax highlighting, file loading/saving và nhiều editor functionality khác. ([Gnome Pages][3])

Như vậy mình **không tự viết những thứ nhàm chán**, nhưng vẫn giữ cái lõi mà Remin cần tự làm: workspace, tab/pane, persistence, snapshot, restore, plugin surface và UX.
